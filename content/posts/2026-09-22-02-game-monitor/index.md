## 起因

我发现自己玩游戏时容易超过原本设定的时间，而且单靠临时提醒并不总能控制住，于是做了一个监视程序，把“少玩一点”变成可以执行的规则：监视指定游戏进程，累计当天使用时间，在不同时间点提醒，并在工作日达到上限后关闭目标游戏。

这个项目使用 Codex 协作完成。它针对的是 Windows 桌面环境，目标是控制一个明确选择的游戏程序，而不是扫描或管理所有正在运行的程序。

## 程序结构

项目是一个 .NET Framework 4.5 的 WPF 桌面程序。主界面分成三部分：

- “监视状态”：显示目标程序、当天累计时间、各个阈值和最近一次检测结果；
- “监视设置”：选择目标 EXE，设置第一次提醒、第二次提醒、最后预警和强制下线时间；
- “特殊日期”：添加不自动关闭游戏的日期范围。

`MonitorEngine` 使用定时器周期性检查目标进程。它首先按完整路径确认目标程序；如果系统拒绝读取进程路径，则只在找到唯一同名进程时使用降级识别，尽量避免误操作其他程序。检测到游戏运行后，程序按时间差累加当天使用秒数，并定期保存。

## 规则和关键步骤

默认规则是 30 分钟、60 分钟、75 分钟和 90 分钟四个阶段，但界面要求用户输入的四个时间严格递增，因此可以自行调整。工作日会执行强制下线逻辑，周末不会执行工作日上限规则。

达到提醒阈值后，程序只对当天各个触发点提醒一次。达到工作日上限后会把当天标记为已阻止，并尝试关闭目标程序：先请求主窗口退出，等待最多三秒；如果没有退出，再调用 `taskkill /PID ... /T /F` 关闭目标进程树。程序关闭后，当天再次启动该目标程序时仍会继续阻止。

特殊日期仍保留每 30 分钟提醒，但达到上限不会自动关闭游戏。程序还可以把代码中记录的法定节假日范围加入豁免列表。管理员密码用于首次初始化、修改设置、退出程序、添加或删除特殊日期，以及重置当天累计时间。密码使用随机盐、PBKDF2 和 Windows 当前用户数据保护进行保存。

## 持久化和交付物

配置、每日使用记录和触发记录通过 XML 保存到当前用户的 LocalAppData 下的 `GameMonitor` 目录，运行日志也写在那里。程序还包含：

- 开机自启和最小化到托盘；
- 单实例互斥，避免同时启动多个监视器；
- 未处理异常写日志；
- 设置文件临时写入后替换，减少保存中断造成的损坏；
- `GameMonitor.sln`、WPF 界面、模型、服务类和 Debug/Release 构建产物。

## 当前结果和边界

当前目录中已经有可编译的 WPF 项目和生成的 EXE。它实现的是“指定程序、按日期累计、分级提醒、工作日强制关闭、特殊日期豁免”的完整流程。它不是系统级家长控制，也不会限制其他游戏或绕过管理员权限；如果系统拒绝结束进程，程序会提示需要更高权限，但不能保证强制关闭一定成功。

项目目录没有提供完整的测试报告，因此这里不把进程关闭、开机自启和所有节假日日期称为经过全面验证的生产级功能。节假日表是代码中维护的固定数据，未来年份需要继续补充或更新。当前也没有公开的独立代码仓库链接。

## 运行前提

项目面向 Windows，使用 Visual Studio 或兼容的 MSBuild 打开 `GameMonitor.sln` 后构建。第一次运行需要设置管理员密码，然后选择需要监视的游戏 EXE 并保存规则。若要让程序在达到上限后关闭权限更高的游戏进程，可能需要以管理员身份运行。
